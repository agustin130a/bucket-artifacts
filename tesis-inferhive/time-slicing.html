Time-slicing en la RTX 3090

Varias personas usan la misma GPU a la vez, por turnos. La 3090 de knode11 se ofrece como 3 slots: cada alquiler toma uno, o los tres si se pide la GPU completa.

Lectura: 5 min · Diseño completo en docs/PLAN-gpu-slicing-3090.md

La idea en un dibujo

Cómo está armado

Hay dos piezas. Para que funcione tienen que estar activas las dos.

Kubernetes

El nodo anuncia 3 GPUs

Un ConfigMap tiene la configuración knode11-shared con replicas: 3. Un sidecar del device plugin lee la label nvidia.com/device-plugin.config del nodo y recarga el plugin sin reiniciar nada.

k8s/51-nvidia-device-plugin-timeslicing.yaml

Portal

El portal vende 3 ventanas

Con GPU_SLOTS="knode11=3" el portal deja abrir hasta 3 ventanas a la vez en el nodo. Un lock por nodo evita que dos reservas se queden con el último slot.

app/slicing.py · k8s/40-portal.yaml

Un pod que pide más de una réplica se rechaza en la admisión (failRequestsGreaterThanOne), y cada namespace de alumno tiene una quota de 1 GPU. Nadie puede quedarse con la tarjeta entera desde el spec del pod.

Qué ve el alumno

Un slot

0,817 PC/h

Tarifa del nodo dividida por 3. En ofertas aparece «Ahora (2 de 3 slots libres)». Le tocan unos 8 GB de VRAM, sin garantía.

GPU completa

2,45 PC/h

Toma los 3 slots al precio del nodo entero. Solo se puede si no hay nadie en ningún slot, y mientras dura nadie más entra.

En un nodo compartido se cobra el tiempo que se tuvo el slot, con un piso del 25 % del tiempo reservado. No se puede medir con DCGM porque DCGM ve la tarjeta, no el pod. Por el mismo motivo, la parada automática por inactividad está apagada en ese nodo.

El flujo de un alquiler

  1. El alumno alquila un slot (o un job toma uno; los jobs siempre usan 1).
  2. El portal toma el lock del nodo y verifica que el pico de slots ocupados más el nuevo no pase de 3.
  3. El reconciler le da quota de 1 GPU al namespace del alumno. Con el primer slot ocupado, el Ollama de knode11 se apaga.
  4. El pod pide nvidia.com/gpu: 1, el scheduler le asigna una réplica y CUDA reparte el tiempo entre los procesos.
  5. Al terminar, se libera el slot y se liquida con metering = 'sliced'. Cuando se libera el último slot, Ollama vuelve.

¿Por qué solo la 3090?

Es la única placa del clúster con VRAM suficiente para repartir: 24 GB dan unos 8 GB por slot, que alcanzan para un 7B cuantizado, un notebook de PyTorch o Stable Diffusion 1.5. En una placa de 4 GB, como la 1650, cada slot quedaría inútil. MIG, que sí aísla memoria, no existe en placas GeForce.

Sumar otra placa

  1. Agregar una configuración al ConfigMap y aplicarlo. 
    knodeX-shared: |
  version: v1
  flags: { migStrategy: none }
  sharing:
    timeSlicing:
      renameByDefault: false
      failRequestsGreaterThanOne: true
      resources:
        - name: nvidia.com/gpu
          replicas: 2
  2. Etiquetar el nodo. 
    kubectl label node knodeX nvidia.com/device-plugin.config=knodeX-shared
  3. Ampliar la variable del portal y hacer rollout. 
    GPU_SLOTS: "knode11=3,knodeX=2"

El orden importa. Para activar, primero la label y después la variable. Para volver atrás, al revés: primero se deja de vender slots, se espera que terminen las ventanas abiertas y recién entonces se quita la label.

Cómo probarlo

# tests unitarios y de manifiestos
pytest tests/test_gpu_slicing.py tests/test_gpu_slicing_manifests.py

# en el clúster: el nodo debe anunciar 3
kubectl describe node knode11 | grep -A2 'nvidia.com/gpu'
kubectl -n kube-system logs ds/nvidia-device-plugin -c config-manager

# rollback
kubectl label node knode11 nvidia.com/device-plugin.config-
  • Tres alquileres de cuentas distintas conviven y ven la misma GPU (mismo UUID). Un cuarto queda Pending.
  • Una «GPU completa» con slots ocupados se rechaza.
  • Un OOM intencional en un pod hace fallar a los vecinos: sirve para ver qué le aparece al alumno.
  • En settlement_metering esas ventanas quedan con metering = 'sliced'.
Lo que time-slicing no da No hay aislamiento de memoria ni de fallos: un error Xid reinicia los 3 slots. El cómputo tampoco está garantizado: tres entrenamientos pesados van a 1/3 cada uno. Si esto se vuelve un problema real, las alternativas son MPS o HAMi.
